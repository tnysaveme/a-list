## Measurements and operational observations

[Local benchmarks](measurements/implementation-2026-10-26.json) record CPU/serialization, first-page payloads, per-process rebuild coalescing and a controlled provider-wait budget. They do not establish production capacity or database round-trip costs.

[Live provider probes](measurements/providers-2026-10-26.json) used four fixed public titles, each searched once and repeated once. First-pass p50 was about 334 ms and p95 about 1,950 ms; repeated-pass p50 was about 301 ms and p95 about 320 ms. All eight searches returned without degraded-provider status. These small samples came from this machine and do not measure Redis cache hits or the authenticated production API.

Read-only checks found the A-List Supabase project healthy, the existing QStash schedule active, and source status recently successful with zero failures. Supabase advisors still report the pre-existing private service-only tables without public policies, three historical foreign-key index notices, and the password-protection setting warning. This work did not relax RLS or enable password sign-in; it does not claim to have resolved unrelated provider advisories.

The provider backup response listed no physical backups and PITR was disabled. No plan/billing changes were made. Application backup tooling is narrower than a full project backup: Auth identities/settings, sessions, storage and provider credentials are excluded. The owner explicitly chose not to export live rows.
